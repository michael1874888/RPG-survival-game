# 奈奈 v0.10：構築實驗試玩

更新：2026-11-15。v0.10.0 是奈奈的能力與遭遇實驗，沿用橫向雙手操作、抓咬與主動大絕。三連戰、隨機抽選和正式十分鐘局仍未製作。主畫面已整理成奈奈構築實驗入口；下列 APK 是整理前的版本。

## 開始試玩

Mac 可雙擊專案根目錄的 `Play.command`；手機安裝方法與最新 APK 見 [Android 安裝說明](android-install.md)。目前原始碼：選「選擇能力與情境」→ 選 0–2 個能力及情境 →「開始實驗」。已交付的 v0.10 APK 仍使用舊選單：選奈奈 →「構築實驗」。選零個能力可作基準；也可以用 A＋B、A＋C、B＋C 快速組合。

| 能力 | 怎麼用 |
| --- | --- |
| A 穿影爪 | 爪擊三次命中後，從觸發位置朝原方向追加一次窄長爪影；空揮不直接清除計數，太久未命中會歸零 |
| B 游走蓄勢 | 放開攻擊並移動，蓄滿後下一次命中的爪擊更寬、更重；空揮保留蓄勢 |
| C 獵痕重咬 | 重咬先在存活目標上留痕；追擊可加速蓄咬，再次咬中同一獵物兌現。獵痕目標僅在重咬扇形內優先，不自動轉向 |

橫向雙手：左側拖曳移動、右側拖曳瞄準並持續攻擊、放手停止；右下方按鈕釋放大絕。Mac 使用 WASD／方向鍵、按住滑鼠左鍵與空白鍵。左上顯示重咬與已裝能力進度；淺藍弧提示當下預計重咬目標，粉色菱形／圓環標示 C 獵痕，兩者可能不同。

三個情境分別測清路、混合威脅、精英與支援，每段最多 60 秒遊戲時間，完成所有必要出生且清場即可提前結束。每場重設生命、蓄力和大絕；擊敗精英沿用既有恢復 20 生命。到時間未完成會顯示未完成，玩家死亡顯示失敗。結算可同配置重試或更換能力與情境。

## 建議對照順序

1. 清路：先不裝能力，接著單裝 A、單裝 B；再重玩一次單裝 A，留意是否因熟悉而改變。
2. 強敵帶支援：先不裝能力，再單裝 C；觀察能否看懂目標、守住獵痕與完成兌現。
3. 如果還想比較，再到同一個混合威脅情境試 A＋B、B＋C，最後複測 A＋B。可分次試玩，不需要手抄秒數。

回饋最有用的是哪個操作讓你改變走位、何時想放手、想咬的敵人是否容易選到、哪套還想再玩，以及哪裡遮住或不舒服。這些體感不能由自動控制器取代。

## 開發驗證與界線

- 先前 v0.10 自動檢查紀錄見 [執行紀錄](test-results-v0.10.txt)；主畫面整理後的檢查結果見 [交接文件](../../HANDOFF.md)。
- 固定控制器對七種能力配置各跑三種情境；E1 基礎配置無存活敵人時間 6.6%，E2 基礎配置兩種敵人同時存活 69.8%。控制器自動瞄準與移動，未使用無敵或大絕；這不是玩家勝率、平衡或手機效能。[完整輸出](build-experiment-probe-v0.10.txt)、[重現腳本](../../scripts/research/probe-nana-build.gd)。
- Mac 已實際啟動遊戲，並由 Godot 實際場景擷取實驗選單與戰鬥畫面供版面檢查；該畫面使用測試建立的敵人與狀態，不代表真人完整遊玩。
- APK 為 ARM64 debug，簽章、ZIP、Manifest、權限與封裝內編譯規則已檢查；使用者於 2026-11-15 確認已在 Android 手機試玩，回饋「目前測試起來體感ok」。手機型號、Android 版本與逐項觸控／效能紀錄未提供；開發端 adb 當時未偵測到裝置。詳見 [首輪回饋](../design/poc-feedback-and-followups.md)。

## 開發紀錄

每局結束、重開或返回選單時，程式嘗試把事件及取樣資料寫到 Godot 的私人使用者資料目錄 `user://build-experiment/`，包含配置、平台、事件、攻擊、受傷、輸入與位置；結果畫面若無法儲存會提示。正常重試與結算不必手動記錄。Android 上實際提取路徑與裝置存取流程尚未驗證；無法儲存或 App 被系統直接終止時不保證有完整紀錄。

規格、具體數值、遭遇時間與驗收條件見 [構築實驗 v2 規格](../design/nana-build-experiment-plan.md)。
