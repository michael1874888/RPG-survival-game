# 手機核心玩法原型：第一輪測試與完成條件

日期：2026-11-13。狀態：測試計畫，尚未取得實機結果。下列次數與門檻為本輪建議，方便驗收與決定下一步，不能當成已通過的紀錄。

## 這輪要回答的問題

1. 手機雙手移動與瞄準是否舒服、可靠？
2. 刺蝟的命中、擊敗敵人與清群回饋是否容易感受到？
3. 選擇升級後，玩家是否看得出攻擊改變，並有嘗試不同選擇的理由？

研究範圍是單一 Android 實機上的三分鐘核心循環。正式美術、更多動物、十分鐘完整局、局外養成、iOS 與廣泛設備相容性留待後續階段。

## 建議的首輪測試方式

先花約 10–15 分鐘，玩 3–5 局並記錄實際存活時間。第一局熟悉操作；之後刻意檢查雙指、升級、暫停與重新開始。首輪主要找問題，不要求第一次就通關。

| 面向 | 怎麼測 | 本輪通過條件 |
| --- | --- | --- |
| 啟動與完整流程 | 安裝、開始、拾取經驗、升級、結算、重玩；連續開玩至少三局 | 無崩潰、卡死或阻擋流程的問題；重玩重設生命、經驗與升級 |
| 雙指操作 | 同時移動與瞄準；分別抬起左右手；暫停後再恢復 | 左手不誤射、放開右手停止攻擊、抬起一根手指不打斷另一根；恢復後沒有卡住的輸入 |
| 可讀性與清怪回饋 | 留意尖刺命中、敵人退場、受傷、衝刺預警及 UI 邊緣 | 能辨識命中與受傷，能理解至少一次受傷／失敗原因；必要資訊與按鈕可見、可點 |
| 升級與構築 | 比較至少兩種攻擊行為升級，例如散射與穿透／反彈 | 玩家能描述差異及用途；選完後有可察覺的改變，操作仍清楚 |
| 穩定性與中斷 | 敵人較多時移動瞄準；切到背景再返回 | 無持續影響瞄準的卡頓；返回後保持暫停，明確繼續才恢復計時與戰鬥 |

若隨機選項未讓玩家遇到所需升級，記為「未測」，下一版可用固定選項的測試情境補驗，不要求反覆刷到指定選項。若無法接近三分鐘，記錄難度與失敗原因，由開發端檢查壓力配置；不要求玩家以反覆嘗試代替問題修正。

## 怎樣算完成

**首輪測試完成：**留下設備與版本、3–5 局觀察、各項通過／失敗／未測結果，以及最優先的問題。即使發現不好操作，這也是有效測試結果。

**核心原型可進入下一階段：**

- 上表必要項目已在實機驗證，沒有尚未修正的流程阻塞、雙指錯誤或重大可讀性問題。
- 成功與失敗兩條結算及重玩路徑都在手機驗證過；首次成功可在開發者明確標記的受控測試情境補驗，正常模式的通關難度另列平衡結果。
- 使用者認為基本操作可以接受，命中與清群有明確回饋，且能描述至少兩種攻擊變化的不同用途。
- 修正後有針對原問題的複測紀錄；剩餘小問題已列出，並有明確下一步。

若操作或構築體驗仍不成立，就在本階段修正再測。是否想再試一種構築可作體驗訊號，但少量個人測試不能代表長期留存或市場驗證。

```text
本次玩了幾局、各局存活多久：
測到的升級：
雙指操作：通過／失敗／未測；具體現象：
命中、受傷與預警是否清楚：
最能感到不同打法的升級，以及原因：
暫停、返回與重新開始：

```

首次可先以文字回饋，不必準備完整錄影或效能報告。效能數值門檻需在確認目標手機與量測方式後設定；目前不宣稱已達特定 FPS、耗電或溫度目標。
