# 奈奈 v0.31：夜巡 X1 手感與回饋重做

2026-11-20。玩法、數值與內容都和 [v0.30](nana-v0.30-practice.md) 相同，這一版只重做「玩起來的感覺」：畫面、特效、音效、音樂、觸覺與介面動畫。設計原則見 [手感設計](../design/x1-feel-design.md)，調整方法見 [調參指南的「手感與回饋」](x1-tuning-guide.md#手感與回饋)。**還沒有經過手機實玩**，震動的實際手感、音量與手機效能都要等試玩確認。

## 這一版改了什麼

- **重量分級的回饋：**爪擊雜兵只有輕脆的聲音和火花；咬中、兌現有短暫停頓、震屏和震動；擊敗獵物或精英有金色爆發、光柱和慢動作；夜影啟動、守關轉階段與被擊敗有鏡頭推近、全畫面閃光和專屬震動。常見的事很輕，少見的事才重，避免敵人多時變成一片噪音。
- **角色與特效：**奈奈改成會呼吸、擺尾、跑動傾斜、撲擊時先壓縮再拉長、落地擠壓、咬擊張嘴的程式繪製角色；敵人依種類有不同輪廓，受擊會擠壓、蓄力時鼓脹變紅，收招時有「空檔」。擊殺會碎裂成碎片和影煙，撲擊有殘影與速度線。
- **聲音：**每個事件都有自己的音效（多數有 2–3 種變化、音高隨機），連續擊殺與撿經驗的聲音會沿五聲音階往上爬。每區有一首會隨戰況加入鼓、旋律與守關層的音樂，收網、升級、勝利、失敗另有短音樂；低血量時音樂變悶、加心跳聲。
- **觸覺：**改成有輕重與節奏的震動（輕點、咬擊、重擊、升級兩下、收網三下、夜影與守關的長段、低血量心跳），每 70 毫秒最多一次，重要的優先。
- **介面：**
  - 血條扣血時先留白色殘段再退。
  - 小魚乾會從獵物飛向左上的計數。
  - 目標獵物以菱形打勾顯示。
  - 畫面外的獵物、精英、守關會在邊緣出現箭頭。
  - 撲擊次數是右手旁的弧形格子，夜影是會發光的能量環。
  - 連獵計數在右上，跨過 10／25／50／100 時放大並放射光芒、換稱號。被打中會「斷」。
  - 傷害數字預設只顯示重擊（咬、兌現、處決，以及對獵物、精英、守關的命中），擊殺時只顯示實際扣掉的血量。
- **流程動畫：**
  - 進戰鬥有爪痕形狀的轉場與標題卡。
  - 地圖上奈奈的小頭像會沿路走過去。
  - 升級時「升級！」浮在奈奈頭上，卡片依序翻開，進化有特寫。
  - 寶箱打開才揭示寶物。
  - 結算數字以計數動畫跑出來。
- **設定：**音樂與音效分開調音量、震動（關／弱／中／強）、震屏強度、特效（高／中／低）、傷害數字（重擊／全部／關）、低閃光、減少動態（關掉停頓、慢動作與推近，震屏減半）、顯示每幀時間。舊設定會自動帶過來。
- **自動降特效：**手機上若連續 2 秒每幀超過 20 毫秒，會自動降一級特效並提示一次。

## 試玩時想知道的事

不用特別安排，照平常玩就好。若方便，請記下：

1. 撲擊、咬中獵物、收網時夠不夠爽？哪個時刻最有感覺，哪個太弱？
2. 畫面會不會太亂，或看不清楚危險？紅橘色的預警有沒有被特效蓋住？
3. 震動會不會太多、太煩，或太弱感覺不到？（設定可調強弱）
4. 音樂和音效會不會吵？哪個聲音聽久了會煩？
5. 手機有沒有變卡、變燙？可以在設定打開「顯示每幀時間」，敵人很多時看左下角的數字。
6. 手機型號與 Android 版本。

## 開發驗證與證據界線

- **自動測試：**`bash scripts/test-game.sh` 全數通過。舊版回歸 4,563 項；X1 784 項——資料 39、戰鬥 39、敵人 73、卡片 96、局與存檔 243、場景流程 33，新增手感 85、時間 8、音訊 168。
  - **手感：**每種事件對應到正確等級的提示、停頓與震屏有上限、觸覺節流與優先順序、同一幀同一聲音只播一次、連獵計數／門檻／中斷／逾時、傷害數字三種模式與擊殺時不顯示溢出傷害、浮動字不重疊、守關登場橫幅顯示名字、低閃光／減少動態／震屏 0%。
  - **時間：**停頓與慢動作只改變多久跑一步，模擬步長固定 1/60 秒；穿插停頓與慢動作跑 900 步，和直接跑 900 步的整局狀態逐位元組相同。
  - **音訊：**每個音效變體與音樂檔都存在、能載入、長度合理，音樂循環長度一致。
- **逐格錄影：**用 `tests/x1_record.gd`（固定 60 fps）把十個關鍵時刻錄成聯絡表逐格檢查，並修正了看到的問題：
  - 連獵門檻原本是蓋住戰場的全寬橫幅，改成右上計數放大並放射光芒。
  - 「升級！」原本是全寬橫幅，改成浮在奈奈頭上，等級數字跳一下。
  - 多個浮動字會疊在同一處，改成自動錯開，並保持在畫面內、HUD 與橫幅下方。
  - 擊殺守關跳出「1199999」這種溢出數字，改成只顯示實際扣掉的血量。
  - 守關登場橫幅沒有名字，原因是事件欄位名稱撞到事件種類；同一問題也讓非追逐型敵人的死亡動畫畫錯身形，兩者都已修正。
  - 守關擊破時「守關擊破！」和「收網！」同時出現，合成一個橫幅。
  - 受傷時整個畫面的紅閃太重，降到 0.3 倍，只保留紅色邊框為主。
  - 橫幅改成置中的漸隱色帶，位置提高、字變小。
- **效能（Mac，1280×720）：**用 `tests/x1_perf.gd` 維持畫面上 120 隻敵人、持續擊殺、每 40 幀撲擊一次、夜影充滿就放。
  - 最初每幀 22.6 毫秒（約 44 fps）。原因是 Compatibility 渲染器裡每個多邊形、圓、弧和抗鋸齒線都會各自建立頂點緩衝。
  - 把敵人身體、眼睛、粒子、寶石與草叢改用著色貼圖和 `draw_primitive` 後降到 8.4 毫秒，也就是這台螢幕的 120 Hz 上限。
  - 其中模擬加回饋約 0.65 毫秒、建立繪製清單約 1.6 毫秒、渲染 CPU 約 1.9 毫秒，在計畫「呈現層每幀 6 毫秒以內」的目標內。
  - 特效中、低兩級也都在 120 Hz 上限。
  - 這台 Compatibility 渲染器量不到 GPU 時間。**手機數字尚未量測。**
- **畫面：**用 `tests/x1_visual.gd` 以 16:9（1280×720）與 20:9（1600×720）截圖檢查每個畫面、三個區域與三個守關。
- **聲音：**`scripts/x1-make-audio.py` 會印出每個檔案的峰值與 RMS，用來避免爆音和音量不一致。實際聽感要在手機喇叭與耳機上確認。
- **觸覺：**測試只記錄呼叫的名稱與節奏；**實際手感一定要在手機上確認**。
- **Android：**v0.31.0／versionCode 31、ARM64 debug，39.6 MB（v0.30 是 37.7 MB，音訊約增加 1.9 MB）。
  - 已另外驗證簽章（與先前相同憑證）與 Manifest（唯一權限為震動）。
  - 匯出檢查確認呈現層腳本、`feel.json`、全部 64 個音效與 16 個音樂檔都已打包。
  - 從 APK 取出編譯後的腳本與資料，另跑舊版與 X1 規則檢查，都通過。
  - 路徑與 SHA-256 見 [建置收據](../../tools/android-build.json)。
