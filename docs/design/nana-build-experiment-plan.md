# 奈奈構築實驗：第一個可玩版規劃 v2 修訂稿

**Status:** in progress · **Updated:** 2026-11-15

**版本提示：**本文件以下保留 v0.10 規格與歷史驗證；v0.11 的能力修正獲使用者「符合預期」回饋後，依其繼續指示製作 [v0.12 三連戰](../development/nana-v0.12-practice.md)。單場能力規則見 [v0.11 說明](../development/nana-v0.11-practice.md)，跨段與能力最新規則以 [v0.13 說明](../development/nana-v0.13-practice.md)及程式為準。

**v0.10 實驗場已實作，Android 首輪試玩回饋整體體感 OK；能力行為差異仍待比較。** 使用者在補正規劃後指示「好 開始做吧」，授權製作本版實驗場；三連戰及隨機構築仍為後續候選。基準為 `main @ 0bc6f12`（v0.9.0），現行變更以工作區程式為準。能力數值與測試目標仍是待真人驗證的起點。[v0.10 試玩說明](../development/nana-v0.10-practice.md)

## 1. 這一版要回答什麼

**同一隻奈奈換能力後，玩家的站位、瞄準、停手時機與目標選擇，是否出現能描述、能觀察的差異？** 同時記錄是否願意再用不同組合；實驗場可以觀察短期再試意願，但不能代表正式模式的長期重玩。

對象是喜歡清怪成長、願意用雙手操作的手機玩家；先由使用者提供方向與體感回饋，不能據此推論廣泛玩家偏好。沿用橫向左移動、右瞄準並持續攻擊，以及主動冷卻大絕。

- 數秒循環：讀取威脅 → 移動與瞄準 → 爪擊清路、重咬處理重點目標 → 選擇持續壓上或退開。
- 一輪實驗：選能力 → 玩短遭遇 → 看精簡摘要 → 換組合或同配置重試。
- 後續問題：能力差異成立後，再研究段間選擇、隨機機會與完整一局；本版不驗證這些結論。

依據：[v0.9 設計盤點](nana-v0.9-design-audit-2026-11-14.md)、[隨機構築研究](../research/random-driven-combat-mode-feasibility-2026-11-14.md)、[已確認方向](game-direction.md)，以及使用者於 2026-11-15 提供的外部 review／v2 提案和本輪討論。本稿採納能力與量測改進，修正週期推算，將三連戰後移；沒有新增競品實測結論。

## 2. 本次製作範圍

新增「奈奈・構築實驗」入口，提供 **3 個能力、可裝 0–2 個、3 種短遭遇**。各能力只有一級，不可重複裝備；戰鬥中不可更換。製作必要提示、簡單結算與開發紀錄，再交付 Mac 可玩版本及 Android 測試 APK。

Android 真實安裝、雙手操作與效能紀錄列為本版實機驗收項目，須註明設備與平台；APK 匯出成功不等於實機驗收完成。開發可交付與實機驗收分開記錄。

三連戰是實驗場通過後的獨立小里程碑，本版不先製作其入口或跨段狀態。本版也不加入隨機候選、商店、重抽、貨幣、局外養成、新角色／敵種、正式美術、十分鐘局長或新 Boss。主畫面整理後只保留構築實驗入口；v0.9 的掃群／狩獵規則及歷史資料仍可供開發研究。

## 3. 共用戰鬥底座

沿用未選專精的奈奈：普通爪擊保有扇形多目標與對追逐者的既有擊退；命中累積三格，再於下一次有合法目標的出手追加單目標重咬。追加重咬的那次普通爪擊不蓄咬。重咬維持既有重擊互動，大絕維持既有傷害、保護、增幅與冷卻規則。

現行基準為爪擊傷害 10、間隔 0.42 秒、距離 145、全角 100°；重咬傷害 14、距離 175、全角 55°、前搖 0.1 秒。來源：[角色程式](../../game/scripts/nana_combat.gd)。重擊可打斷衝撞者／投擲者前搖；守衛／精英在收招時被重擊可延長該次收招，沿用原有上限與抗性。來源：[敵人程式](../../game/scripts/nana_encounters.gd)。

本實驗的所有配置新增「預計重咬目標」提示，與 C 獵痕採不同形狀；未蓄滿時可低調顯示，蓄滿時強調。它依當下條件預覽，不保證稍後命中，也不替玩家轉向。C 以外沿用中心線優先、同角度取近者的選敵。

每場不掉經驗、不升級。開始時重置為 100 生命、移速 260、大絕就緒，並重置位置、朝向、敵人、所有計數、獵痕及待發攻擊。三種組合都保有基本清路與救場能力；若基礎配置無法合理接敵，先校準共用底座或遭遇，不靠必裝能力補回基本生存。

## 4. 三個能力

**[ASSUMPTION] 以下名稱、數值與裝備上限是試玩起點，尚未實測。** 本版以不同攻擊形狀／目標規則拉開差異；這是本次實驗的設計選擇，不限制未來只能用形狀變化。每個能力單獨可用，裝兩個的成本是放棄第三個。

| 能力 | 一句話規則 | 預期打法 | 代價 |
| --- | --- | --- | --- |
| A 穿影爪 | 每第三次命中的爪擊，追加一道窄長穿透爪影 | 轉換角度，讓前排與後排落在同一道攻擊方向 | 窄角需要瞄準與敵人排列；久未命中會失去計數 |
| B 游走蓄勢 | 不攻擊時移動蓄勢，下一次命中的爪擊更寬、更重 | 在交戰中停手退開，找角度再切入清路 | 蓄勢期間不能攻擊；是否真的少打有效攻擊要由紀錄確認 |
| C 獵痕重咬 | 重咬留痕，再咬中同一目標可兌現重咬 | 在混戰中持續把重點威脅留在前方，完成兩口咬擊 | 目標離開窄角、換咬他人或獵痕過期會失去這次機會 |

### A：穿影爪

1. 每次普通爪擊至少命中一個判定前仍存活的敵人，計一次；同次多人只計一次。觸發重咬的那次普通爪擊、B 強化爪擊都算。
2. 相鄰有效命中間隔超過 1.2 秒，計數歸零；空揮不直接清零，也不延長期限。第三次命中後計數歸零。
3. 觸發後 0.12 秒，以觸發時的位置與朝向作一次傷害判定：距離 340、全角 24°、傷害 8；扇形內每個活敵最多命中一次，敵人不阻擋其他敵人。使用現有扇形對圓碰撞判定。
4. 這是延遲後的一次長窄扇形攻擊，不是飛行投射物；不追蹤、不跟隨玩家。延遲中敵人可以離開範圍。
5. 爪影不擊退、不算重擊、不增加蓄咬或連擊、不觸發其他能力，也不吃大絕倍率。

爪擊 10 加爪影 8 可擊敗同時吃到兩者的 18 生命追逐者；只吃爪影的後排不會因此一擊死亡。多目標只放大這道額外攻擊的總傷害，不能直接換算整套輸出倍增。

### B：游走蓄勢

1. 只有攻擊輸入未啟用時，由移動輸入造成的實際位移才累積；按著攻擊但沒有敵人仍不累積。撞牆未移動、位置修正、暫停和命中停頓不計距離。
2. 累積 260 遊戲單位蓄滿，最多存一發；部分進度不因出手歸零。按基準移速約需一秒移動，不等於每次都犧牲一秒本來打得到的輸出。
3. 滿蓄勢時，普通爪擊傷害增加 12、距離改為 175、全角改為 180°。至少命中一個活敵才消耗，空揮保留；每敵仍只受一次爪擊傷害，單次多人也只消耗一發。
4. 同次追加的重咬不吃 B 加成，大絕不消耗蓄勢，爪影不繼承蓄勢。滿蓄勢保留到命中或本場重置。

22 傷害可一擊擊敗現行追逐者；調整 B 時保留此門檻，若敵人生命一併變更則重新檢查。是否值得停手取決於當下能否有效輸出與能打中多少敵人，不預先宣稱打單體一定虧。

### C：獵痕重咬

1. 普通重咬實際咬中且目標存活時，留下 4.0 秒獵痕，全場最多一個。獵痕不附加 v0.9 狩獵的破綻增傷。
2. **扇形內黏著：**重咬出手選敵時，若有效獵痕目標仍存活且符合當次重咬扇形／距離判定，優先選它；否則依現行中心線規則。不自動轉向、不超出重咬範圍追蹤。
3. 普通爪擊命中判定前仍帶有效獵痕的目標，且本次原本允許蓄咬時，額外加一格，上限三格；同次多人只額外一次。即使這爪擊殺目標，該次有效命中仍可領取額外格，隨後清痕。追加重咬那次出手不蓄咬。
4. **兌現：**重咬實際命中時，若對方仍是有效獵痕目標，該口基礎傷害由 14 改為 36，隨後清除獵痕；即使目標存活，也不立即重新留痕。下一口普通重咬才可再留痕。
5. 咬中其他目標時不兌現，先清除舊痕；新目標存活則轉移並重設四秒，若被咬死則不留新痕。獵痕目標死亡或時間到即清痕，不返還蓄力。
6. 選敵在出手時決定；0.1 秒後仍按既有規則檢查鎖定目標與出手方向。留痕、轉移、兌現均以實際命中為準。若期間獵痕過期，該口只算普通重咬；揮空不兌現、不轉移，原獵痕繼續自然倒數。
7. 普通與兌現重咬都只沿用一次既有重擊處理，且僅在目標存活時處理；不增加第二次控制、不繞過重擊抗性或收招延長上限。

### 週期推算與限制

以下為靜止單靶、每爪／每口都命中、無大絕、忽略走位與敵人反擊的算術參考；時間為遊戲時間，自第一爪在零秒起算，包含重咬 0.1 秒與爪影 0.12 秒延遲。**不是實作、Godot 探針或真人驗收結果。**

| 配置 | 理想穩態 DPS | 260 生命靶逐筆計算的擊敗時間 |
| --- | ---: | ---: |
| 基礎 | 32.1 | 8.08 秒 |
| 單裝 A | 38.5，約增加 20% | 6.72 秒 |
| 單裝 C | 40.8，約增加 27% | 6.30 秒 |

基礎為 `(4 × 10 + 14) / (4 × 0.42)`；A 再加 `8 / (3 × 0.42)`。C 兌現後清痕，因此穩態交替三次／四次出手出一口，為 `(7 × 10 + 14 + 36) / (7 × 0.42)`，不是永遠每三次出一口。理想 C 第一口在第 4 次出手、兌現第 7 次、再留痕第 11 次、再兌現第 14 次，第 16 爪即可擊敗此靶；不能由總血量除以穩態 DPS 代替有限血量的出手序列。

### 組合、回饋與共通邊界

| 組合 | 待驗證的使用方式 | 要留意的問題 |
| --- | --- | --- |
| A＋B | 蓄勢選角度切入，連抓時讓爪影打到後排，再退開 | 持續攻擊與停手蓄勢的時機是否有選擇，而非固定照表操作 |
| A＋C | 持續對重點目標接敵，同時找能穿到其他敵人的方向 | C 的黏著與 A 的瞄準需求能否兼顧 |
| B＋C | 找強敵空檔切入，再決定追擊獵痕或退開蓄勢 | 退開與四秒獵痕窗口是否產生可用取捨 |

- A＋B：蓄勢爪擊只計一次連擊，爪影仍用 A 自己的數值。B＋C：蓄勢爪擊按 C 規則額外蓄一格。A＋C：爪影命中獵痕沒有額外效果。所有額外傷害不遞迴觸發能力。
- 大絕沿用對普通爪擊與重咬的倍率，包含 C 兌現。B 的 +12 在大絕傷害倍率前加入，距離以 175 乘既有大絕距離倍率，角度維持 180°；A 依自身固定數值。
- A 的計數與爪痕放在瞄準側，用與重咬三點不同的形狀；B 用蓄勢進度、爪部發光及滿蓄勢提示音；C 用獵痕、兌現音效與命中閃光，區分預計重咬目標。先以短描述與重複觸發確認玩家理解，不要求完全不讀說明就能理解所有因果。
- **[ASSUMPTION]** B 蓄勢命中與 C 兌現命中各請求 0.05 秒全局戰鬥停頓，以前景且非暫停的實際時間倒數。共用一個計時器，以剩餘時間與新請求的較大者處理，不累加；停頓中不推進攻擊、敵人、出生、獵痕、蓄力、冷卻與場次時限，輸入仍可更新，結束後採最新輸入。
- 暫停／切到背景同樣凍結戰鬥計時；死亡、重開及結算清空待發攻擊與能力狀態。停頓中切背景或死亡不得殘留全局停頓。
- 所有能力特效讓位於攻擊預警。若辨識或觸控瞄準有問題，先查回饋、判定與遭遇，不直接增加傷害。

## 5. 三種短遭遇

**[ASSUMPTION] 每段上限 60 秒遊戲時間。** 沿用現有敵人數值與特殊攻擊並發限制。表中時間是排入一秒出生預警的時間，不是接敵時間；使用獨立固定事件表與場地錨點，不使用隨機補怪，也不依能力換敵。

| 情境 | 首輪事件表 | 要形成的選擇 |
| --- | --- | --- |
| E1 清路 | 0 秒 8 隻追逐者；2、4、6、8、10、12、14、16 秒各 4 隻，左右交替，共 40 隻 | 選退路、轉換攻擊角度、找穿透與半圓攻擊的機會 |
| E2 混合威脅 | 0 秒 5 隻追逐者＋1 隻投擲者；4 秒 1 隻守衛＋3 隻追逐者；10 秒 1 隻衝撞者＋1 隻投擲者＋4 隻追逐者；15 秒 4 隻追逐者，共 20 隻 | 在近身壓力下選擇接近、清路或集中威脅 |
| E3 強敵帶支援 | 0 秒精英＋3 隻追逐者；2、8、14、20、26、32、38 秒，在精英存活條件下各追加 3 隻追逐者，最多 25 隻 | 支援仍在干擾時，選擇清小怪或追擊精英 |

E3 首次追加從八秒提前為兩秒，但仍須由實際接敵紀錄確認支援及時到場。固定錨點、預警、安全距離與移動時間共同決定壓力；出生數量不直接等於包圍，也不能保證 E2 每次都有相同重疊。

### 事件、容量與勝敗

- 每個事件保留編號與狀態：未排入、預警、等待安全重試、已出生、條件取消。容量 45 包含在場、預警與安全重試；取消與出生後死亡的事件不佔容量。三種表的總數都低於容量，不代表手機效能已驗證。
- 錨點候選依固定角度與半徑產生；偏好位置不安全或與其他預警太近時，依確定順序尋找目前畫面內的其他固定候選。預警完成時若不安全，保留同一事件並重新完整預警，不抽其他敵種、不丟棄事件、不複製重試。走位仍會影響實際遭遇，不能稱為完全相同的重播。
- E3 初始精英尚未出生時，條件支援暫候，不把「尚未出生」當作「已死」。精英一旦死亡，取消尚未進入預警的未來支援，標記原因為「精英已擊敗」；已進入預警／安全重試的支援完成原流程，不突然消失。合法條件取消不是漏生。
- 所有必需事件已出生或合法條件取消、待出生隊列清空、敵人全滅才成功。生命歸零失敗；到上限仍未完成顯示「未完成」。同一步生命歸零優先判失敗。
- 漏生、重複出生或未解決的必要事件在開發紀錄標記資料無效，不作成效比較；玩家介面不顯示「這場不算」。缺怪也不能顯示一般清除成功：未解決事件仍存在時，達上限顯示「未完成」，提供立即重試。
- 每場獨立重置，不跨段累積生命或冷卻；擊敗精英沿用既有恢復 20 生命的規則。事件數量、時間、錨點校準後記規則版本；所有對照使用同一份設定，不替強勢組合臨時補壓力。

### 交付前校準

先以基礎配置和有紀錄的代表性自動輸入檢查接敵、出生與空檔，再跑單能力及組合。自動輸入證明規則可用與情境能提供機會，不證明真人會採用預期打法。

- **[ASSUMPTION] 校準觀察目標：**基礎配置在 E1 的無存活敵人時間低於有效場次時間的 10%；在 E2 有兩種以上敵人同時存活的時間超過 50%。同時檢查可見、可接敵的敵人，避免遠處活怪讓指標看似通過。這些比例是待校準起點，不是趣味或所有組合的通關門檻。
- 基礎配置須能合理接敵、閃避、造成傷害並推進事件，不以全部通關為要求。若強勢組合快速清除威脅、降低重疊，先確認是有效收益，不為了達比例而否定它。
- A 在 E1 要看到多次穿透與後排命中機會；B 要看到交戰窗內停手蓄勢、消耗與再次蓄勢；C 在 E3 要能看到留痕、兌現，以及另設的失去目標／過期檢查。各自記實際樣本數，不要求每種能力同場觸發十次。
- 若支援還沒到精英就死亡，先查出生與接近時序；如果前排被清後一直空等，先查事件間隔與方向。依紀錄調整同一套遭遇，不為湊觸發數刻意要求玩家留怪。

**v0.10 開發觀察：**初始事件表讓固定控制器在 E1 無怪 47.9%，E2 因出生錨點持續不安全而留下四個待出生事件。調整為上述間隔及確定式固定候選錨點後，同一控制器的 E1 基礎配置無怪 6.6%、E2 混合敵種同時存活 69.8%；七種配置各跑三種情境，共 21 場的事件均完成或依精英死亡條件取消。控制器自動移動／瞄準、未用無敵或大絕，不能推論真人手感、勝率或裝置效能。[原始輸出](../development/build-experiment-probe-v0.10.txt)、[控制器](../../scripts/research/probe-nana-build.gd)。

## 6. 流程與量測

流程為選 0–2 個能力／快速預設 → 選情境 → 戰鬥 → 結算 → 同配置重試或換能力。結算僅顯示組合、結果、遊戲耗時、受傷來源、各能力觸發次數、指定強敵是否擊敗與處理時間；細節留在開發紀錄。

### 紀錄定義

每場保存規則版本、配置、設備／平台／輸入方式、事件編號與狀態／排入／出生時間、玩家輸入／位置／朝向、敵人位置與種類、攻擊目標 ID／來源、實際扣除生命、蓄力／獵痕／大絕事件。傷害扣除量與命中次數分開，不用溢出傷害放大收益；不要求使用者手抄時間。

- 行為狀態以每 0.1 秒遊戲時間為取樣目標，長幀超過取樣間隔時最多每幀取一次，不虛構中間狀態；能力與命中事件逐次記錄。移動距離逐步累積，不用稀疏取樣低估轉彎路徑。
- 保存實際經過時間、遊戲時間、暫停時間及命中停頓時間；60 秒時限與戰鬥指標用遊戲時間，選單／背景／停頓不混入分母。
- **[ASSUMPTION] 交戰窗：**畫面內有距玩家中心不超過 390 遊戲單位的活敵，或有可見敵方彈體。另存無活敵、只有遠處活敵及不符合交戰窗的時間；這是固定的操作性定義，不等於完整危險度模型。
- 各能力分別記觸發、有效命中、目標、時間；B 額外區分蓄勢是否在交戰窗內取得，C 區分留痕、兌現、轉移、過期、目標死亡。沒有有效樣本或分母為零時記為「無樣本」，不填零。

| 行為 | 紀錄指標及控制 |
| --- | --- |
| 停手 | 攻擊輸入啟用時間比例，整場與交戰窗分開；按住空揮也算啟用，記錄重新啟用前的停手段長 |
| 接敵 | 到最近活敵中心的時間加權平均距離；無活敵不納入，交戰窗另算，保留敵人種類與可見性 |
| 走位與瞄準 | 移動輸入造成的實際路徑長、100 單位網格的涵蓋格數、瞄準方向變化；另存怪群重心與成員變化，不將重心跳動算成玩家繞側 |
| 集中目標 | 普通爪擊按連續幾次出手命中指定目標計串長，不依多目標迴圈順序；重咬按連續命中同一目標 ID 計。各自另算對指定守衛／精英的命中佔比，只在該目標存活窗計算；爪影與大絕另列，不混入同一分母 |

### 預先指定的假設

| 能力 | 相對同情境基礎配置的預期 | 輔助紀錄與限制 |
| --- | --- | --- |
| A | 出手前走位／瞄準有更多為穿到後排而作的調整 | 記爪影每次命中數、距離與基礎爪擊範圍外的命中；平均命中兩隻可觀察但不作硬門檻，自動穿到不等於玩家有調整 |
| B | 交戰窗內停手蓄勢及重新切入增加，攻擊啟用比例降低 | 記每次蓄勢命中數與取得時機；平均命中三隻是候選收益目標，不把空檔蓄滿當作交戰中取捨，也不因比例低就直接加成本 |
| C | 在強敵存活窗內更持續對準該目標，完成留痕至兌現 | 記合法扇形內停留、普通爪擊／重咬的集中度、兌現與失去目標原因、強敵處理時間；扇形內黏著本身帶來的命中改善要與玩家轉向分開判讀 |

比例變化與輸出改善都不是單獨的通過證據。能力形狀、選敵黏著和敵人分布本身也會改指標，須對照輸入／位置事件與使用者描述；有大絕時記使用時機，必要時開發端補無大絕對照。

### 使用者試玩順序

先固定同一平台與輸入方式；跨 Mac／Android 的結果分開。第一輪以單能力確認原因，必要時再做組合比較，不要求使用者跑完整矩陣。

1. E1：基礎 → 單裝 A → 單裝 B → 重試單裝 A；每次同一事件表，最後一場用於辨認學習或疲勞影響，不能完全消除它們。
2. E3：基礎 → 單裝 C，確認目標提示、追擊與兌現是否能理解與交付。
3. 若仍有精神與興趣，再選喜歡的雙能力試 E2。若要回答 A＋B 與 B＋C 的差別，另用 E2 的基礎 → A＋B → B＋C → A＋B 短對照，不從跨情境結果推論能力效果。

第一輪六場，每段至多一分鐘遊戲時間，實際總耗時另含說明、操作與回饋，不承諾固定十五分鐘。可分次完成；開發端只補釐清疑問所需的場次。詢問哪裡改變打法、哪裡失誤、是否願意再用不同組合，不把問卷回答等同實際重玩行為。

### 通過與修正

單能力階段先確認至少兩個能力在同情境對照中，輸入／走位／目標紀錄支持預期的行為差異，且使用者能用自己的話指出差異。進入三連戰前，仍須以必要的同情境組合對照，確認至少兩種組合有可描述、可觀察的打法差異，並記錄願意再選／不想再選的原因；不因單能力通過就跳過組合驗證。可分次試玩，小樣本作方向判斷，不宣稱統計顯著、等強或長期耐玩。

若只見傷害變高、行為未變，依序查提示是否清楚、是否有使用機會、收益／門檻是否合理，再決定調參或重做能力，不一律禁止調數值。若手機上窄角或目標交付失敗，先修選敵與提示；若特效蓋住預警，先修可讀性。B 在各情境都採同樣循環也先問是否有趣、是否存在合理替代行為，不直接以提高成本處理。

| 順序 | 問題與界線 |
