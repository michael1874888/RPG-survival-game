# 奈奈 v0.5：機制、規格與核心實作 review

日期：2026-11-14。範圍：目前工作樹中的奈奈 v0.5、第一版戰鬥草案與相關驗證。基準提交為 `840801b`，本輪奈奈程式及規格仍在工作樹。這次交付檢查結果與建議，遊戲規則與 APK 均未修改。

已讀新增的 `game-design-core`、`game-docs`、`create-game-assets`。本輪使用前兩者檢查核心循環、決策、風險回報、規格狀態及證據；美術製作流程依使用者要求延後。技能中的英文正規表示式與設計口訣僅作檢查提示，不將文字命中或未命中當成玩法好壞的證據。

## 判斷

保留奈奈、連抓、重咬與主動冷卻大絕的方向。現階段最應處理的是自動重咬與清群的衝突、命中正確性，以及能驗證攻擊價值的敵人情境。四種敵人、構築、精英與 Boss 可維持分段規劃，尚未實作的項目不列為 v0.5 缺陷。

| 編號 | 優先度 | 類型 | 結果 |
| --- | --- | --- | --- |
| R1 | 高 | 已量測的設計風險 | 自動重咬會取代範圍爪擊，群體總傷害可能下降，玩家無法直接拒絕這次替換 |
| R2 | 高 | 測試情境缺口 | 現有練習可零攻擊通關，不能以通關證明攻擊、大絕或目標選擇有價值 |
| R3 | 中 | 已重現的實作錯誤 | 爪擊扇形外緣與側邊交界會命中實際沒有相交的敵人 |
| R4 | 中 | 擴充風險 | 敵人傷害及練習限制依角色 ID 分支，新增敵人或完整奈奈模式前需分清資料歸屬 |
| R5 | 中 | 規格維護缺口 | 部分入口仍寫待設計／待 review，與 v0.5 已實作的狀態不一致 |

## R1：自動重咬可能懲罰清群

位置：[奈奈攻擊實作](../../game/scripts/nana_combat.gd)，49–80 行；[構築草案](nana-combat-design-v1.md) 的「成長與兩種構築」。

三次成功爪擊後，下一次攻擊會改成單體重咬：傷害由多目標各 10，改成單目標 24，間隔由 0.42 秒變成 0.60 秒。這能增加單體輸出，卻會減少同次清群覆蓋。替換是自動的，玩家不能維持原方向攻擊又選擇延後消耗；滿格後刻意偏離咬擊扇形可以延後，但會把基本操作變成規避自動行為。

在 Godot 用高生命、零移速的固定目標作 60 秒比較，每幀將目標放回範圍內，排除擊退離開與擊殺的影響；兩組均無大絕。純爪擊組只在探針中壓制準備累積，並非遊戲提供的模式。

| 同時位於爪擊範圍的目標 | 現有自動重咬總傷害 | 純爪擊參照總傷害 | 現有連段相對變化 |
| --- | ---: | ---: | ---: |
| 1 | 1,704 | 1,390 | +22.6% |
| 3 | 3,624 | 4,170 | −13.1% |
| 6 | 6,504 | 8,340 | −22.0% |

這證明特定受控情境的收益衝突，不能直接推論玩家一定覺得重咬不好，亦非目前 18 生命追逐者的實戰勝率比較。加入厚血混合敵人前，這個風險值得先收斂。

**推薦調整提案：** 優先比較「保留該次爪擊，重咬作單體追加終結」的版本；仍然三次成功命中準備、仍然不增加重咬按鍵。重新評估追加傷害與恢復節奏，驗證清群不會因自動觸發而退步，也不令單體輸出失控。若改採可手動保留的終結技，須另外評估手機操作成本。以上尚未改成規格或程式。

## R2：目前成功條件不能驗證戰鬥決策

位置：[場次規則](../../game/scripts/run_model.gd)，134–146、183–200、272–274 行；[v0.5 試玩範圍](../development/nana-v0.5-practice.md)。

奈奈移速 260，追逐者移速 90；目前只有追逐者、無攻擊目的地限制，180 秒存活即可成功。用四個固定導航點繞圈，不攻擊、不放大絕，也不修改生命或無敵，結果如下：

| 種子 | 結果 | 剩餘生命 | 擊敗數 |
| --- | --- | ---: | ---: |
| 1 | 180 秒成功 | 44 | 0 |
| 7 | 180 秒成功 | 60 | 0 |
| 11 | 180 秒成功 | 52 | 0 |
| 71 | 180 秒成功 | 60 | 0 |
| 901 | 180 秒成功 | 4 | 0 |

這是五個固定種子的模擬，不代表所有路線或玩家都能輕鬆繞過戰鬥。存活成功符合目前練習的既定規則，不能列成勝利判定 bug；問題在於這種情境不足以區分攻擊、大絕及選擇目標的價值。

**推薦處理：** 保留三分鐘自由練習；下一個小里程碑先做有明確問題的短戰鬥，例如固定敵群的清除時間，再加入少量衝撞者、投擲者，分別觀察側移與接近優先目標。由開發端比較攻擊命中、擊敗時間、受傷來源、大絕釋放前後的局勢，玩家只需回饋體感。先不以增加血量、拉長局長或加入更多成長系統解決這個驗證缺口。

## R3：扇形邊角存在實際誤判

位置：[奈奈命中判定](../../game/scripts/nana_combat.gd)，120–129 行。

目前把「距離小於攻擊距離＋敵人半徑」和「角度小於半角＋敵人角度寬度」分別判斷；兩項都通過，不保證圓與有限扇形真的相交。

重現：爪擊距離 145、半角 50°，放一隻半徑 17 的敵人在距離 160、方向偏移 55°。敵人中心到最近扇形角點的距離為約 20.039，大於半徑 17，應未相交；實際爪擊仍造成 10 傷害。使用的是目前追逐者半徑。

**推薦修正：** 以敵人中心到有限扇形的最近距離判斷是否小於半徑；分別涵蓋扇形內、圓弧與兩條有界側邊。補上外緣角點的相交／不相交檢查。目前測試只覆蓋一般前後位置，未捕捉這個邊界。

## R4：場次限制與角色能力仍混在一起

位置：[場次規則](../../game/scripts/run_model.gd)，188、256–257、272–274、347–355、428–429 行。

目前追逐者的接觸傷害由玩家角色決定：奈奈一律用 8，其他角色再按敵人種類用 10 或 16。未來直接把衝撞者接入奈奈，也會走奈奈分支；程式沒有敵人自身的傷害資料欄位。奈奈不掉經驗、不升級與只出追逐者，也都以 `character_id == "nana"` 控制。

這符合本次練習的暫時範圍，但「奈奈角色」和「固定能力練習場」不是同一件事。未來奈奈需要成長、不同敵人也有不同傷害，不能只替換角色攻擊就完成。

**推薦整理：** 先用敵人定義保存生命、速度、傷害及攻擊階段；由場次設定控制敵人池、是否升級、時間與勝利條件；由角色保存攻擊及大絕。受傷無敵可屬角色／防禦資料，敵人的基礎傷害由敵人提供。這是一個有實際需求的小幅分工，不需要先建完整通用技能框架。

## R5：文件檢查通過仍有語意狀態漂移

位置：[主題與角色方向](theme-and-characters.md)，19、24 行；[開發路線](development-roadmap.md)，87–91 行；[戰鬥草案](nana-combat-design-v1.md)，14 行。

奈奈能力已有 v0.5 實作，但角色表仍寫具體攻擊與技能「待設計」；路線與部分推薦表仍寫大絕效果／數值「待 review」。這容易讓接手者重新討論已同意的試玩起點，或把完整構築也當成已完成。

`game-docs` checker 以既有長篇草案為入口掃描 34 份 Markdown（含本報告），0 errors、0 warnings。它另回報 `gdd-no-index`，表示這個文件格式不採 feature index，狀態索引比對被跳過；這不是文件錯誤，也不需要改造目錄。工具不會自動理解中文段落的語意矛盾。

**推薦整理：** 在原文件內將連抓、重咬、大絕及追逐者標成「已實作／手感待驗證」；把其他敵人、專精、精英及 Boss 標成「已設計／尚未實作」。保留歷史紀錄並註明被哪個決策取代；用連結引用同一份數值與驗收依據，減少重複維護。

## 建議的核心處理順序

1. 修正扇形邊界，對齊當前已實作／待驗證的規格狀態。
2. 收斂自動重咬的清群衝突，以受控比較與實際操作檢查。
3. 分開角色、場次與敵人資料；先做最少量的衝撞／投擲壓力，補足奈奈的反擊與大絕時機。
4. 核心行為成立後再做兩種構築、精英與 Boss，逐步接成約十分鐘的一局。
5. 正式美術、故事、角色擴充與完整介面風格在上述核心收斂後討論。

維持目前既有方向：單一角色、手機雙手操作、主動冷卻大絕、快速重新開始、可區分的敵人預警，以及玩家回饋與程式驗證分開記錄。這些都適合作為後續基礎。
