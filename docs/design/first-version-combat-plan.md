# 第一版：單一角色與敵人戰鬥設計

更新日期：2026-11-14。狀態：使用者已確認先聚焦一個角色，先設計角色攻擊與機制，再設計敵人種類、特色、攻擊及機制，之後處理其他部分；保留其他角色的擴充空間。

本文件是目前設計工作的順序與交付要求。未實作的能力、敵人與數值依設計草案逐步細化；以小型可玩版本修正手感與平衡。

目前 [奈奈與第一版敵人戰鬥設計草案 v1.1](nana-combat-design-v1.md) 涵蓋推薦玩法、攻擊規則、敵人、構築、節奏、起始數值及交付步驟。使用者負責 review 與方向決策，Codex 負責提出方案、拆分工作及後續開發驗證。

使用者已同意以目前推薦方案開始。第一個里程碑已完成 [奈奈 v0.5 手感試玩](../development/nana-v0.5-practice.md)：連抓、重咬、冷卻大絕與追逐者；其餘敵人與構築依試玩結果接續。草案細節與數值可繼續調整。

## 第一版範圍

- 第一版主角已改為使用者家中的黑貓，角色名為「奈奈」，集中完成牠的戰鬥體驗。
- 使用者要求有可主動釋放、帶冷卻時間的大絕招；抓、咬可融入攻擊，能力形式可延伸，具體方案由 Codex 評估並提出推薦。
- 刺蝟與小熊保留為歷史原型；約克夏保留為未來候選，其他角色安排在單一角色與敵人核心完成之後。
- 角色設計完成後，接著設計第一版敵人及其混合壓力，再整合戰鬥循環。
- 完整主題、故事、正式 UI／美術、完整震動系統與其他周邊功能排在這組核心設計之後。讓攻擊、命中與危險可讀的必要占位提示仍屬戰鬥設計。
- 第一版敵人數量、精英／Boss、完整局長與勝利條件在角色及敵人設計時決定；歷史三分鐘原型與約十分鐘目標不是新增內容承諾。

## 一、先完成一個角色

先描述玩家如何操作、何時有優勢、何時需要退讓，再決定技能與數值。

| 設計項目 | 要定清楚的內容 |
| --- | --- |
| 戰鬥定位 | 擅長清除什麼敵人、適合什麼距離、主要風險，以及希望玩家採取的走位與瞄準方式 |
| 基礎攻擊 | 輸入、出手節奏、方向、射程、覆蓋、命中與結束條件；移動中能否攻擊 |
| 大絕與其他能力 | 大絕的主動輸入、效果、冷卻起算、持續時間與使用時機；是否需要其他防禦或位移，以及操作負擔 |
| 成長與構築 | 專屬／共通升級、前置、上限、疊加與觸發順序；每條路線如何改變打法 |
| 生存規則 | 生命、受傷無敵、擊退／控制、恢復方式，以及危險時可做的選擇 |
| 可讀性 | 發射、命中、落空、受傷與能力可用狀態的必要提示 |

奈奈以使用者描述的「抓人、咬人」作為動物特色依據，允許童話式誇張。具體基礎攻擊、抓與咬如何分工、距離、節奏、能力、升級與生存機制，接著逐項設計；這些行為尚未直接定為兩個技能。

使用者進一步確認：抓、咬不限制整套能力，只要經過評估，影子、誇張動作或其他適合奈奈的攻擊形式都可納入提案。現有抓／咬方案可保留，需說明相較替代方案的取捨。

既有橫向雙手、左移動／右側方向輸入作為操作設計依據，需配合奈奈的攻擊形式確認細節。刺蝟的尖刺、散射與反彈試玩結果保留為歷史參考，奈奈的能力與資源規則需依牠的玩法定義。

角色設計產出應包含：一頁玩法說明、攻擊／能力規則表、升級與互動表、玩家典型操作，以及需要試玩的未知。先形成可對照的完整草案，再進入敵人詳細設計；敵人若揭露角色問題，可回頭調整。

## 二、再完成第一版敵人

每種敵人先有清楚的戰鬥用途，再配置外形與數值。下列是需要評估的壓力方向，不是已核准的敵人名單：包圍逼近、預警突進、遠距威脅、限制安全區域。精英／Boss 是否必要，依這組敵人能否形成完整一局再決定。

每種敵人都要寫清楚：

1. **用途與特色：** 它讓玩家面對什麼問題，與其他敵人有何差異。
2. **行為與攻擊流程：** 接近／選位、準備、鎖定、預警、攻擊、收招與再次行動；哪些階段仍會追蹤玩家。
3. **應對與破綻：** 玩家能靠走位、瞄準、攻擊優先順序或能力如何處理，何時可以安全反擊。
4. **傷害與互動：** 接觸是否傷害、命中範圍、能否打斷／擊退，以及與角色攻擊和升級的關係。
5. **出場與提示：** 安全生成、視野外攻擊限制、輪廓及預警的可辨識方式。
6. **組合與限制：** 和誰同場、各自數量及攻擊重疊限制，避免所有退路同時被封死。

既有追逐與預警衝刺型是原型素材，可沿用或調整；它們已可運行，不代表第一版敵人設計已完成。

## 三、角色與敵人一起檢查

- 先用單一敵人確認提示、應對和破綻，再逐步混合，最後安排一局中的教學、壓力升高、喘息與結束。
- 檢查同一角色的升級選擇是否改變瞄準、站位或目標優先順序，以及是否存在任何情況都最好的選項。
- 角色與敵人都要有可描述的規則和應對；數值以試玩調整，避免只靠加血、加傷害製造差異。
- 規則完整不等於手感通過；開發驗證與使用者手機體感分開記錄。

## 四、保留其他角色的擴充空間

實作時遵守以下邊界，依本輪需要逐步整理：

- **角色定義獨立：** 基礎屬性、專屬攻擊、能力與升級池可各自配置。
- **共用戰鬥規則：** 傷害、命中、受傷無敵、狀態與擊退、經驗、局內成長及結算，由共用規則處理。
- **攻擊形式可替換：** 投射物、近戰、區域或其他形式可以各自實作，透過共用命中與效果規則與敵人互動。
- **敵人依戰鬥資訊行動：** 依目標的位置與狀態決策；避免依刺蝟名稱或尖刺形式寫死應對。
- **升級有適用條件：** 區分專屬與共通效果；未來近戰角色不必接收只適合投射物的選項。
- **場次與角色選擇分開：** 出怪、關卡節奏和結束規則可搭配不同角色。

這些是擴充要求；目前仍以完成第一個角色為交付單位。
