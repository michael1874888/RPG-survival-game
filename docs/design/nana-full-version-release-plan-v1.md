# 奈奈第一完整版 D1：製作、試玩與發布門檻

**Status:** R1 playtest build delivered; R2 and R3 pending · **Updated:** 2026-11-20。

依據：[主設計](nana-full-version-design-v1.md)、[內容表](nana-full-version-content-v1.md)。使用者已確認開始實作，v0.20 首章試玩包及驗證範圍見 [試玩說明](../development/nana-v0.20-practice.md)；R1 的玩家與手機驗收仍待進行。本文件的目標數字是 **[ASSUMPTION] 專案內部判準**，不是產業基準、目前成績或上架保證。

## 1. 什麼叫第一完整版

第一完整版需要同時滿足四件事：內容從開始到結尾完整；玩家理解並願意使用主要機制；日常手機中斷與存檔可靠；發布內容、權利及平台包均已完成。美術可以簡潔，但內容、可讀性與可靠性不能留給第二版補救。

| 首發承諾 | 完成內容 |
| --- | --- |
| 角色及操作 | 一位完整奈奈，抓／咬／主動大絕；手機多點觸控、可調控制區、練習場與漸進引導 |
| 一局 | 九個戰鬥節點、兩次營地路線、成長、失敗、勝利、結算、自主再玩 |
| 構築 | 三核心、六成形、24 種天賦、容量限制、合法候選、保證機會、有限刷新與一次微調 |
| 裝備 | 十二件真實可得寶物、兩格分工、定向尋寶、無重複收藏、完整圖鑑與 v0.19 遷移 |
| 遭遇 | 三章、八種普通敵、兩種精英、三個獨立 Boss、十八張完成場地、完整有限編排及混合安全限制 |
| 長期目標 | 主線結尾、三級難度、六種狩獵記號、十八項成就與個人紀錄 |
| 產品功能 | 可靠續玩、匯出／匯入、設定、說明、製作名單、音訊與輔助選項；無假按鈕或不可取得卻宣稱可得的內容 |
| 發布交付 | Android 可安裝完整包、iOS 實機與發布包、版本收據、商店資料、隱私與授權資料、已知問題與支援入口 |

這是完整範圍，不把技能組合的數學排列數當作內容量。三章也必須玩起來不同，不能只用底色、HP 係數與 Boss 名字充數。

## 2. 三批交付，逐步做完同一款遊戲

所有批次都沿同一個遠征主流程前進，舊固定實驗入口留在開發工具，不把玩家主畫面變成測試模式清單。沒有日期承諾；每批以完成條件驗收，不為趕里程碑降低後一批標準。

| 批次 | 可交付範圍 | 使用者實際要玩的內容 | 進下一批的條件 |
| --- | --- | --- | --- |
| **R1：完整循環試玩** | 首章九節點、六成形；15 天賦：M01／M02／M05／M07／M09／M10、S01／S03／S05、G01–G06；六件首章寶物；E01–E05、兩精英、B01；六事件；標準與輔助；收藏／續玩／練習／結果與基本呈現 | 一次正常出發，取得東西，自選下一局換裝；至少比較兩套構築與一次風險選擇 | 玩完試裝局仍有自己的下一個目標，能解釋至少兩個升級取捨；沒有卡關、存檔或控制阻塞。若只剩開箱有感，回頭改主循環 |
| **R2：首發內容完成** | 補齊主設計與內容表全部首發內容；三章、24 天賦、十二件寶物、八普通敵、三 Boss、三級難度、十八成就、十八場地與完整編排 | 從新存檔到主線結尾，再選自己想找的裝備／挑戰；可玩到收藏完成 | 首發所有承諾都能在正常遊戲取得／完成，分支及章節有可描述的差異；完成外部試玩與平衡修正 |
| **R3：發布候選** | 內容凍結、裝置／效能／存檔測試、iPhone 交付、Android release、發布文案／截圖／權利／隱私／支援 | 完整包長時間玩、鎖屏、續玩、更新後繼續；正式候選版走全流程 | 達到第 5–7 節門檻，才稱 v1.0 候選；上架本身另依使用者確認執行 |

R1 是讓使用者確認整體好不好玩的完整循環，**不是可直接拿去正式商店當 v1.0 的縮水版**。R1 介面只顯示它實際提供的內容；完整收藏成就等到完整池完成才啟用。

iOS 技術風險不拖到最後：R1 開發時先以小型內容驗證一次 iOS 匯出、觸控、安全區及暫停／恢復；R3 才完成正式簽署、發布與全部內容的設備驗證。若 Apple 開發者資料或可測裝置尚無，記為平台交付阻塞，不以 APK 取代。

不為這版先造任意角色／卡牌／效果編輯器。資料需要支援表中實際內容與驗證即可；系統之間仍保留角色攻擊、敵人、成長、收藏、場次的責任分界。

### 存檔及遷移的必要細節

- 保存 profile 與 active-run 的同一交易版本；暫存完整寫入並驗證後才替換正式資料，保留上一份有效版本。遷移失敗保留原檔並報錯，不用新空檔覆蓋。
- 快照包含敵人 ID／位置／HP／AI 階段／計時、投射物、待發爪影／重咬、出生與重試保留、波次、事件進度、玩家與能力狀態、地面掉落、經驗、候選、各亂數串流及已領獎勵集合。
- 房間完成／選卡／開箱使用穩定交易 ID，保存成功才推進完成畫面。繼續已完成交易時直接重建結果，不能再扣點或重領。
- 暫停、退到背景不消耗時間；背景保存完成不保證 OS 永遠留住程序，因此週期快照與關鍵交易保存都需要。
- 保留既有 Android 套件、更新簽章與 Godot 使用者資料目錄；若改顯示名稱會影響資料路徑，必須先做可驗證遷移。Android 與 iOS 不假定能自動互通存檔。
- 新版進入選單前跑舊存檔遷移；已有鈴鐺不得再要求解鎖。測試收藏流程使用獨立測試資料，不能清玩家進度。

## 4. 怎麼驗證真的更有趣

### 4.1 先看使用者的自然行為

首輪不指定每局必須選哪件裝備，也不在結算提醒再玩。交付只說目前可玩內容及如何開始；有引導測試與自主行為分開記。

| 時點／問題 | 紀錄 | 如果沒有發生 |
| --- | --- | --- |
| 戰鬥是否要作判斷？ | 至少一次為威脅而轉換站位／目標、蓄勢或開大；事後能指出原因 | 先修遭遇與回報，不加更多圖鑑 |
| 升級是否值得選？ | 有一次因當局血量、敵人或已持有效果改選；選後可觀察行為差異 | 重寫效果或候選，不能只加卡片數 |
| 新物品是否拉動下一局？ | 領取、看說明、選裝、實際開局、實際使用分開記錄；看練習不算開局 | 先查取得時點、效果理解與再次出發摩擦 |
| 試用後還想做什麼？ | 試裝局結束先看去向，再問「你現在最想做什麼，為什麼？」 | 區分只想開箱、只喜歡變強、戰鬥沒變化或時間不足 |
| 後一天是否想回來？ | 在沒有提醒的情況下是否主動啟動、有無自選目標 | 先蒐集原因；單一玩家不能推論整體 D1 留存 |

先讓使用者玩出整體感覺，再問三題：最想再試什麼？哪個選擇最值得想？哪一段最想停？不要求使用者替團隊設計關卡或填完整統計表。

### 4.2 發布前的外部試玩

招募約 20 位符合目標的初次玩家，以自然遊玩和可自由停止的方式觀察；需足夠時間容許重開，但不強迫玩滿。以下是內部的方向門檻，樣本小，不作市場成功或因果證明。

| 指標 | 操作定義 | 初始門檻 |
| --- | --- | --- |
| 理解基本玩法 | 無旁人代操作／口頭教學，能移動、攻擊、使用大絕並進到第一營地 | 至少 14／20 |
| 自主再開 | 第一次有機會結算／放棄後，在同次測試實際開始第二個遠征；練習、看裝備與按鈕誤觸不算 | 至少 12／20 |
| 試用後再玩 | 首次裝備試用局結束後，仍自主開始另一個遠征 | 在實際走到此觀察點的人中至少一半；同時報告分子、分母與未走到原因 |
| 跨次回來 | 首玩後 24–72 小時內，沒有遊戲獎勵通知或研究員提醒而自主開始遠征 | 至少 8／20；只有自願回報／有同意紀錄者才能判定，缺失另列，不當成已通過 |
| 有意義的差異 | 能描述至少兩個構築如何改變操作、哪種遭遇適合它，不只說傷害變大 | 至少 12／20 |
| 終點後仍有玩法 | 另外找六位願意玩到收藏完成的玩家，看他們是否自選熟練／另一打法挑戰 | 至少四位有具體行動，作為方向訊號；自願樣本不能推回所有玩家 |

設備錯誤、時間不足、討厭雙手操作、單純玩完滿足等原因保留在原分母及分群紀錄，不為過門檻任意剔除。若加入遠端分析，需另完成告知、同意、隱私及 SDK 查核；預設只用本機摘要及自願回報，不因設計指標預先加入追蹤。

所有目標都通過也不能保證長期留存；未通過時先找具體原因與可驗證修正。若喜歡的人集中在少數流派，先確認是偏好還是其他流派不可用，不立即強制追求平均選率。

### 4.3 只記有助決策的資料

遠征記錄含版本、章節、難度／輔助、種子、起手、裝備、候選／選擇／刷新、節點時間、受傷來源、成形觸發、寶物取得、結算與下一次實際開局關聯。結果區分死亡、放棄、暫存、勝利，不把退出全部當成不喜歡。

本機預設保留最近 20 局摘要、每局事件上限 2,000，舊資料循環覆蓋；不記觸控原始軌跡、身分或其他應用資料。正式包關閉高頻開發輸出。

## 5. 玩法與技術驗收

下列是完整首發門檻，尚未全部完成。R1 已有受控規則、場景及封裝檢查，具體結果與限制見 [v0.20 試玩說明](../development/nana-v0.20-practice.md)；不能以自動檢查代替玩家或手機驗收。

| 驗收面向 | 必須證明的結果 | 方法 |
| --- | --- | --- |
| 構築合法性 | 三張不同有效候選；格位、前置、成形名額、天賦上限與所有刷新／微調正確 | 規則測試＋大量種子路徑；含全選共通、延後第二核心、空習慣格與提前成形 |
| 成長預算 | 各節點經驗精確到表定總額，Boss 前能取得十次；召喚與反覆載入不能刷點；事件額外強化有單獨來源 | 逐節點對帳與快照重載測試 |
| 攻擊互動 | 六成形、24 天賦、十二寶物的有效邊界；無遞迴、重複扣血、無限充能或失效標記 | 有針對性的規則／整合案例，涵蓋牆邊、死亡、失手與多敵同幀 |
| 遠征流程 | 新檔至三章結尾、失敗／退出／暫存／續玩、每個事件成功及失敗，都可回到合法下一狀態 | 真實場景流程測試，不只直接呼叫規則函式 |
| 隨機與公平 | 合法池及保證機會可重現；特殊攻擊／出生容量不超標；必要敵與安全區可達 | 種子批次檢查＋靠牆／角落／密集混合的實機情境 |
| 內容可用 | 空習慣格仍可通過標準；六成形各在三章都有可行路徑，不要求指定稀有卡；支援／Boss 不硬克制 | 開發控制僅檢查可達性，再由真人對照；不把控制器勝率當玩家平衡 |
| 結算 | 致命來源與戰果正確，新收藏不漏、重開不重領；實際使用才計成形熟練 | 紀錄對帳＋場景核對 |
| 存檔 | 舊版遷移、寫入中斷、磁碟滿、資料損壞、重複讀取均不靜默清空；匯入先驗證再套用 | 測試副本與故障注入，保留原始玩家資料 |
| 呈現與觸控 | 全部畫面在小螢幕／瀏海安全區可讀可按；雙指加大絕、跨區移動、鬆手、切背景無黏鍵 | Android 與 iPhone 實機；截圖只證明該畫面配置 |

平衡先看「是否有用、能否交付、代價是否值得」，再調數值。每個主要成形至少找到一個擅長情境與一個需要補弱點的情境；若同一套在所有情境更穩、成長更早、又無格位代價，先處理規則而非只提高其他選項傷害。

## 6. 手機與發布品質

### 裝置門檻

- 先用實機鎖定支援下限，再承諾最低 OS；至少測一台下限 Android、一台常見 Android、一台支援範圍內較舊 iPhone、一台有瀏海／動態島 iPhone。同一台可兼具角色，型號與 OS 必須記錄。
- 一般目標 60 fps；保底可選穩定 30 fps。高壓完整跑 30 分鐘：60 檔 95% 幀耗時不超過 20 ms，30 檔不超過 40 ms；任何明顯卡頓都要看實際幀時間與輸入影響，不能用平均 fps 掩蓋。
- 測完整遠征、反覆重開十次及兩次鎖屏／恢復，無崩潰、無持續記憶體爬升、無 OS 過熱中止；音訊中斷與回前台可恢復。記錄熱與耗電觀察，不憑短跑宣稱長期耗電良好。
- 按鈕觸控範圍以平台建議尺寸核對；字體不靠系統缺字補上。降低特效不能移除敵人招式提示。
- 新安裝、同套件更新、離線啟動、檔案匯出／匯入、重開應用續玩都要跑。APK 簽章與 zip／manifest 驗證不能替代手機安裝；iOS 模擬器也不能替代 iPhone。
- 無阻礙遊玩、資料遺失或高頻崩潰問題才進發布候選；低影響問題列入已知清單，不能包括無法完成的首發承諾。

## 7. 確認與版本邊界

1. 是否以「一位奈奈、三章、六種成形」作為首發的深度與內容量。
2. 是否採「習慣寶物提早成形＋一件通用小物」，而非永久加傷或隨機詞綴養成。
3. 是否接受 R1 先玩到完整循環，體感成立後做完 R2、R3 的全部首發承諾。
