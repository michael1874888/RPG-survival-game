# 原創生存動作 RPG：分階段開發路線

建立日期：2026-11-13。狀態：Q1–Q15 與整體原型起點已確認，已獲授權安裝並進入核心玩法實驗。採 Godot 4.7.2 + GDScript；正式版規模及商業模式尚未決定。

目前方向與逐輪討論見 [遊戲方向草案](game-direction.md)。

2026-11-14 最新順序：第一版主角已選定為寵物黑貓「奈奈」，先完成牠的攻擊與機制設計，再完成敵人種類、特色、攻擊及機制，接著整合戰鬥及處理其他部分；保留其他角色的擴充空間。具體產出與順序以 [單一角色與敵人戰鬥設計計畫](first-version-combat-plan.md) 為準。

首輪使用者回饋：目前試玩 OK，認可快速 PoC；後續逐步補足 UI／美術與主題故事、震動等回饋，以及不同動物的攻擊特色。詳見 [回饋與後續事項 F01–F03](poc-feedback-and-followups.md)。

已確認的角色設計原則：專屬基礎攻擊搭配部分共通升級；動物特色可童話式誇張；可愛角色搭配誇張戰鬥及非血腥退場。

已確認的操作與節奏：橫向雙手操作，左側移動、右側拖曳瞄準並持續攻擊、放開停止；連續戰鬥、升級暫停選擇，完整一局先以約 10 分鐘為目標。

已確認的原型範圍：單人離線、刺蝟角色、一張小場地；尖刺基礎攻擊不耗魔且無彈藥限制，特殊能力若加入則採冷卻。

已確認的基本循環：敵人掉落經驗、靠近拾取、升級暫停三選一；敵人先做追逐型，再加入預警衝刺型；角色以生命值承受傷害，受傷後短暫無敵，生命歸零結算並可重玩。

已確認的製作方向：2D 俯視角，第一個完整短版原型存活約 3 分鐘即成功；使用者提供方向與手機實玩回饋，Codex 負責規格、程式與可執行驗證，按小里程碑交付。詳見 [原型 v0.1 規格草案](prototype-v0.1-spec.md)。

## 起點與目標

現有研究圍繞「容易操作、有成長爽感、值得反覆遊玩」的生存動作 RPG，並特別研究法術、局內構築與敵群壓力。原創遊戲希望融合可愛動物元素，讓不同動物的攻擊方式與自身特色產生關聯；角色不限定為法師。研究主要來自官方說明與特定版本的靜態資料，尚未完成受控實玩或玩家測試。

開發先用小型可玩版本回答最重要的問題，再逐步增加系統和內容。各階段的數量與時間在確定平台、團隊和可投入時間後再估算；階段完成不代表必須立刻進入下一階段。

```mermaid
flowchart LR
    A[1 願景與限制] --> B[2 核心玩法實驗]
    B --> C[3 可玩直切版本]
    C --> D[4 擴充與重玩驗證]
    D --> E[5 製作與測試]
    E --> F[6 發布準備]
    B -. 手感不成立 .-> A
    C -. 體驗不成立 .-> B
    D -. 範圍或樂趣不足 .-> C
```

## 階段 1：確立遊戲方向與開發邊界

- **要回答：** 玩家是誰？主要平台及操作裝置是什麼？玩家每局做什麼、感受到什麼？專案有多少人力、時間和預算？
- **討論取捨：** 自動攻擊或主動瞄準；是否管理魔力；連續生存或波次間休息；單局長度；單機或連線。這些選項要以目標體驗與製作成本一起判斷。
- **產出：** 一頁遊戲願景、核心循環、設計支柱、目標平台與限制、明確不做清單，以及待驗證假設。
- **完成條件：** 能用具體的玩家行為描述遊戲，選定第一個測試平台與原型比較問題；重要未知仍可保留，但要有驗證方式。

## 階段 2：核心玩法實驗

- **要回答：** 移動、攻擊與閃避本身是否舒服？加入瞄準或資源後，帶來的決策是否值得操作負擔？
- **工作：** 依階段 1 的選擇比較適合的引擎與工作流程；用占位素材製作最小戰鬥場景，包含移動、至少一種攻擊、一種敵人、受傷與重新開始。必要時做可切換的操作方案，讓同一問題能直接比較。
- **產出：** 可執行原型、操作及技術選型紀錄、短次數測試觀察與修改清單。
- **目前聚焦：** 先完成黑貓奈奈的定位、攻擊、能力、成長與生存規則，再設計第一版敵人與應對；F03 的其他角色比較排在單一角色與敵人核心完成後。
- **完成條件：** 在目標輸入方式上可重複測試；玩家能理解如何移動、攻擊及生存；團隊能指出手感問題並決定繼續、調整或回到階段 1。具體測試人數與判準在實驗前訂定。

## 階段 3：完成一小段完整遊戲體驗

- **要回答：** 戰鬥、升級選擇、敵人壓力和結算接起來後，是否形成有趣的完整一局？
- **工作：** 以少量原創法術、行為確實不同的升級、敵人及一段壓力變化，串起開始、戰鬥、成長、失敗或勝利、結算及再玩一次。只加入驗證該循環所需的介面、音效與視覺回饋。
- **產出：** 可從頭玩到結算的直切版本、初版規則與內容表、測試紀錄。
- **後續回饋 F01／F02：** 完整主題、故事、正式 UI／美術與震動整合，排在角色及敵人核心設計之後；戰鬥辨識所需的占位提示隨核心一起處理。
- **完成條件：** 沒有阻礙完成一局的重大問題；觀察者能說出升級如何改變打法及失敗原因；根據測試決定核心循環是否值得擴充。

## 階段 4：驗證構築與重玩

- **要回答：** 不同選擇是否改變實際打法？隨機與規劃是否兼顧？玩家想再玩一局的原因是什麼？
- **工作：** 增加少量可對照的構築路線與敵人情境，檢查選項可讀性、取得機會、強弱差與局長。只有在核心需求明確時才試驗局外進度；將它與局內樂趣分開評估。
- **產出：** 構築及敵人設計表、不同玩法的測試記錄、修正後的首發範圍。
- **完成條件：** 至少能在測試中觀察到兩條有意義的打法，以及玩家對重玩或停止的具體原因；不足時縮小或重做設計，不靠增加內容數量掩蓋問題。

## 階段 5：正式製作與測試

- **要回答：** 確定的範圍能否以現有人力做完，並在目標設備上穩定運行？
- **工作：** 依測試結果製作正式美術、音效、內容與介面；建立存檔、設定、無障礙需求、效能和錯誤處理；安排內容整合、相容性及玩家測試。具體功能依平台和產品範圍決定。
- **產出：** 內容完整的測試版、已知問題與優先順序、效能及相容性結果。
- **完成條件：** 約定的首發內容完成，重要流程與目標設備測試通過，剩餘問題有明確處置。

## 階段 6：發布準備與後續決策

- **要回答：** 遊戲是否達到約定的品質門檻？如何交付、取得回饋及維護？
- **工作：** 依已選平台準備發行資料、授權與素材權利檢查、版本管理、安裝更新及回報方式；決定是否進行小範圍測試。商業模式、帳號及線上服務若有需要，再另行評估。
- **產出：** 發布候選版、發布檢查結果、已知限制與後續支援計畫。
- **完成條件：** 發布門檻與未解問題經專案負責人確認，並依選定的發行管道完成必要要求。

## 現在的下一步

最新交接以根目錄 [HANDOFF.md](../../HANDOFF.md) 為入口。[v0.9 設計盤點](nana-v0.9-design-audit-2026-11-14.md) 已指出專精與比較方法需收斂；接著完成 [Balatro 式隨機構築研究](../research/random-driven-combat-mode-feasibility-2026-11-14.md)。分段隨機構築是待 review 推薦，尚未批准製作，以下保留既有階段脈絡。

依最新決策，先按以下順序推進：

目前 [奈奈與第一版敵人戰鬥設計草案 v1.1](nana-combat-design-v1.md) 已供 review，包含下列角色、敵人及整合規劃。使用者負責方向決策，Codex 根據 review 收斂規格後分段製作；草案不代表已核准實作清單。

第一個可玩里程碑：[奈奈 v0.5 手感練習](../development/nana-v0.5-practice.md) 已完成，包含連抓、重咬、主動大絕與追逐者；目前已加入四種普通敵人的固定短情境；手機操作及手感待 review。

1. 以黑貓奈奈為第一版主角，評估抓、咬及其延伸形式，完成戰鬥定位、基礎攻擊、主動冷卻大絕、升級互動與生存規則的完整草案。大絕與起始數值已實作，手感與平衡待試玩。
2. 依角色能力設計第一版敵人：每種敵人需有不同用途、攻擊流程、提示、應對、破綻及混合限制。
3. 整理角色／敵人互動、出場與壓力節奏，再分段實作及試玩。
4. 核心收斂後接續其他部分；其他角色保留擴充位置與候選紀錄。

詳細要求見 [第一版戰鬥設計計畫](first-version-combat-plan.md)。以下是既有原型依據與仍待驗證事項：

1. 已收到「目前測試起來 OK」的正向回饋，保留快速 PoC 節奏；完整回饋見 F01–F03。
2. [v0.2 刺蝟／小熊攻擊對照 PoC](animal-attacks-poc-v0.2.md) 已收到小熊回饋：近身操作要求較高，較高基礎攻擊力讓體感仍可接受。黑貓與約克夏已記為未來角色候選。
3. [v0.3 構築比較 PoC](build-comparison-poc-v0.3.md) 已交付，使用者回報散射＋反彈明顯更爽，穿透初期不明顯且與反彈部分重疊。固定靶群檢查支持陣形會影響兩組優勢；尚未宣告構築平衡通過。
4. [v0.4 陣形比較 PoC](formation-comparison-poc-v0.4.md) 已收到使用者回饋：反彈似乎足夠，穿透沒有特別亮眼的地方。保留散射＋反彈方向，暫停穿透與陣形的反覆比較，將穿透移出近期必須深化的路線；既有實驗仍保留，不等於完成兩條有意義構築的驗證。
5. 持續區域與引怪站位是歷史候選，尚未選定；是否使用改由單一角色與敵人的完整設計決定。主題／UI 與震動保留後續清單；正式目標玩家範圍、發售時間及額外預算尚未設定。[目前驗證狀態](../development/prototype-v0.1-status.md) 保留使用者整體回饋與逐項驗收的界線。
